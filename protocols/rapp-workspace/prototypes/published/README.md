# Published workspace prototypes

These files are inert prototype and migration inputs, not current authority
and not normative predecessors requiring a later major version. The sole core
protocol is [`rapp-workspace/1`](../../1/SPEC.md).

The archive preserves the exact source bytes and original labels, including
old claims of normativity, anatomy, compatibility, or authority. Those claims
are historical text, not instructions to execute or current adoption rules.
Original relative links retain their original repository-root context.

[`index.json`](index.json) pins eight files to full Git commits, original
paths, SHA-256 digests and byte lengths:

- both published 1.1 SPEC snapshots;
- both published 2.0 SPEC snapshots;
- the 1.1 and 2.0 README/SKILL entry documents.

`1.1/SPEC.md` and `2.0/SPEC.md` hold each label's latest archived text.
Earlier distinct bytes are under `revisions/<sha256>.md`. Never overwrite an
archived object to make it resemble the core protocol.

No separate published 1.0 SPEC was found in this repository history. The
archive does not invent one or map a core hash to an old estate. Missing source
bytes do not erase the old identifier's meaning. Live migration remains
disabled until behavior coverage, coherent legacy frontiers and native
rebinding are qualified; byte-only evidence is not enough.

Version strings alone cannot establish authority. Current instances use only
the `rapp-workspace/1` validator and exact pin. Neither a generation marker nor
a product name resolves a version collision. Signed estate activation remains
governed exclusively by RAPP/1.
